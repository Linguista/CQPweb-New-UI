Introduction

The CQPweb software that powers this site's query interface has two query modes.

The first, which is selected by default, is Simple Query mode. It comes in two varieties — ignore case (case-insensitive) and case-sensitive. On this site, searches normally ignore case unless you tick the Case-sensitive box next to the query mode menu; the box works in both query modes, and your browser remembers your choice. The case-insensitive variety treats KAOS, Kaos and kaos as the same word, while the case-sensitive variety treats them as three different words. Otherwise, they're identical. This mode can be used to perform basic queries right out of the box with no special knowledge required. You can find more information on this query mode in the tutorial that is linked to the right of the mode button in the query form.

The second query mode is known as CQP syntax mode. It makes complex and powerful queries possible. But with great power often comes great confusion. The purpose of this tutorial is to get users to a decent level of proficiency with this syntax.

 

Query basics

In their simplest form, CQP syntax queries consist of a bracketed expression containing a key, an operator and a value in quotation marks, such as [word="perro"]. Values can be optionally followed by a flag outside the quotation marks (see below for details). Each expression inside brackets searches within a single token or "slot". A series of bracketed expressions searches for phrases. By default, queries can cross utterance boundaries, which is often undesirable. To limit queries to a single utterance, see Special operators.

Note that unlike search engines, which treat multi-word queries as a bag of words (e.g. team sports will find any page with the words team and sports on them somewhere), all CQP queries are positional — each word represents a token or "slot" in the text, and so team sports will only find occurrences of this exact phrase, and not things like sports team or a team that sports colorful uniforms.

 

Flags

On this site, queries are case-insensitive by default, so [word="perro"] will find perro, Perro, PerrO and PERRO alike, since differences in capitalization are rarely of linguistic interest. Behind the scenes, the site adds the %c flag to every value in your query, which is why the query shown above your results contains %c even if you did not type it. (Standard CQP, and most other CQPweb sites, work the other way round: queries are case-sensitive unless you add %c. You can still type %c here; it does no harm.)

There are two ways to search case-sensitively. To make the whole query case-sensitive, tick the Case-sensitive box next to the query mode menu. To make just one value case-sensitive, add the %C flag (with a capital C) after its closing quotation mark: [word="Perro"%C] will find Perro but not perro or PERRO, while the rest of the query still ignores case. %C is an addition of this site's software, not part of standard CQP syntax, and it can be combined with %d (see below) as %Cd.

Queries are also sensitive to diacritics by default, meaning that canto and cantó will be treated as different words. In languages in which diacritics are used systematically, this is what you will normally want. However, if the corpus's source texts are transcribed speech, user-generated content such as social media, or some other source with less-than-perfect transcription or spelling, you may want to perform a diacritic-insensitive query. This is done by adding the %d flag after the closing quotation mark, as in [word="cachai"%d]. This will find both cachai and cachái ([word="cachái"%d] will produce the exact same results).

These two flags can be combined as %cd.

 

Language notes

If your queries aren't producing the results you expect, there are a few things to check:

  • Contractions like al and del are expanded to their component parts: a el and de el. So to search for del hombre you would use this query: [word="de"] [word="el"] [word="hombre"].
  • Multi-word proper nouns normally appear as a single combined word using _ as a separator. To search for El Mercurio, for example, use [word="el_mercurio"%c].
  • Some words have unintuitive lemmas. These are almost always grammatical words. Some examples:
    • el, la, los, las and lo are all lemmatized as el
    • algún, alguno, alguna, algunos and algunas are lemmatized as alguno
    • este, esto, esta, estos and estas are lemmatized as este.
    • él and ella are lemmatized as él.

 

Search operators

Search operators are used to build queries. They allow you to specify whether you want to include or exclude certain values within a given key, select multiple keys or search in multiple values, find anything that matches a set of criteria, and so on.

OPERATOR MEANING EXAMPLE MATCHES
= Equals/matches [lemma="amigo"] All the allomorphs of amigo: amigo, amiguita, etc.
!= Does not equal/match [tag!="V"] All words that are not tagged as verbs.
& And [word="canto" & tag="N"] All cases where the word canto is tagged as a noun.
| Or [word="perro|gato"] All cases where the word is perro or gato.
! Not [lemma="ir" & !word="fue|fuimos"] All the allomorphs of ir that are not fue or fuimos.
( ) Groups items [word="p(re|os|ost)natal"] The words prenatal, posnatal and postnatal.

 

Querying different keys

You may be wondering why you have to use word in every query expression. You actually don't — instead of [word="canto"%d] you can get away with just "canto"%d, for example. But using the full query structure is a good habit to get into, as the short form limits you the default key, word, and most corpora (including COSCACH, the corpus of spoken Chilean Spanish used for the examples here) contain several other keys that are very useful, but which must be named explicitly in queries.

When you first select the CQP syntax query mode, three lists appear below the Start Query button: p-attributes, s-attributes and a-attributes. The p-attributes are the keys that are available for querying. COSCACH contains six of these, as seen in the following table (other corpora have their own):

KEY (P-ATTRIBUTE) DESCRIPTION MATCHES
word Ordinary words, as found in source texts. comiéramos
lemma Lemma or "dictionary form" of word. comer
pos Full part of speech. VMSI1P0
spos Short part of speech. VMS
tag One-letter basic part of speech tag. V
subtag Three-letter basic part of speech subtag. mai

Key names are case-sensitive, and so must always be entered in lower-case. On this site their values are case-insensitive by default, as explained in Flags above. If you tick the Case-sensitive box or use the %C flag, remember that lemma and subtag are always lower-case, while pos, spos and tag are always upper-case.

We've already examined the word key. Now let's see what the other keys contain and what they're good for.

Lemma (lemma)

A lemma is the citation form of a word — it's what you look up in a dictionary (such as be, as opposed to was, been or am). A lemma includes all of a word's morphological variants, or allomorphs. Some people pluralize this term as "lemmata". We kindly invite you to join our effort to not do this.

When working with Spanish, a far more morphologically complex language than English, querying by lemma is the only convenient way to handle nouns and adjectives, and the only sane way to deal with verbs. A query as simple as [lemma="amigo"] finds amigo, amiga, amigos, amigas, amiguito, amiguitos, amiguita and amiguitas — as well as Amigo, Amiga, Amigos, Amigas, Amiguito, Amiguitos, Amiguita and Amiguitas. Not surprisingly, AMIGO, aMiGo, amiGO and other forms with variations in their capitalization are also matched by this query. Once you start using lemmas, you'll never go back (unless you're studying specific morphological variants across word classes or something else along these lines).

There's no need to use the %c flag when querying the lemma key, as the tagger that we use (the Chilean Spanish version of FreeLing) does not consider case when lemmatizing.

Part of speech (pos)

These are the full part of speech (POS) tags assigned to each word by the FreeLing tagger. If you want to find all plural feminine common nouns, for example, you'd perform the following query: [pos="NCFP000"]. And if you want to find all first-person singular auxiliary verbs used in the present subjunctive, you'd use this query: [pos="VASP1S0"]. Querying the pos tag using regular expressions opens up a whole new world of possibilities, as we'll see below. You can find a detailed explanation of the structure of the POS tags on the Tagset: POS Full page under Corpus info in the left-hand column.

Short part of speech (spos)

This key contains short POS tags derived from the full POS tags. These contain less information than the full tags, but are easier and more convenient to use when the additional information is not required. These queries take the form of [spos="NC"], [spos="VAS"], etc. A detailed explanation of the short POS tags can be found on the Tagset: POS Short page under Corpus info in the left-hand column.

Tag (tag)

This key contains one-letter tags derived from the full POS tags. They encode only words' main part of speech (noun, verb, etc.), but they're very convenient, as they're short and intuitive: [tag="N"], [tag="V"], etc. You can find a detailed explanation of the structure of these tags on the Tagset: Tags & Sub-Tags page under Corpus info in the left-hand column.

Sub-Tag (subtag)

This key contains three-letter tags that encode second-level part of speech information. In the case of nouns, the subtag can be com or prp (common or proper); in the case of verbs, it can be aux (auxiliary), mai (main) or sem (semi-auxiliar); and so on. All subtags are unique, so querying [subtag="mai"] will return main verbs only. You can find a detailed explanation of the structure of these tags on the Tagset: Tags & Sub-Tags page under Corpus info in the left-hand column.

 

Querying multiple values in a single key

So far, we've seen how to search for single values only, such as the allomorphs of the noun perro: [lemma="perro"]. However, it's quite common to want to query a series of values, such as a lexical field or several classes of verbs. This is done by entering multiple values separated by a vertical bar (|). Thus, [lemma="perro|gato|catita|pez|gallina"]will retrieve all allomorphs of these five lemmas, while [spos="VAI|VAS"] will find all indicative and subjunctive auxiliary verbs.

 

Querying phrases or sequences of keys

Query expressions can be chained together in order to find phrases, as in [word="el"%c] [word="perro"%c] [word="vago"%c] (remember, the %c flag means case-insensitive). This will find all instances of the phrase el perro vago, but none in which these words merely appear somewhere in the same text (as a search engine would do).

Of course, you can use any combination of keys in such queries: [tag="D"] [spos="NP"] [lemma="malo"]will match all sequences consisting of a determiner followed by a proper noun and then an allomorph of malo.

In order to query two or more keys that are not adjacent, use an empty pair of brackets ([]) plus whatever quantifier you deem appropriate (if you use no quantifier, the empty brackets will match exactly one token or "slot"). The query [lemma="ser"] [] [pos="AQ"] will match any allomorph of ser followed by one other word of any type, and then a qualificative adjective, e.g. son muy buenos or es super joven. The query [lemma="ser"] []+ [pos="AQ"], on the other hand, will allow one or more tokens of any kind between ser allomorphs and the adjective, while [lemma="ser"] []{1,4} [spos="AQ"]allows between one and four tokens of any kind.

In order to incrase the precision of queries, exclusion criteria can be added to the empty brackets. For example, punctuation marks can be excluded from the previous query's wildcard expression by replacing the empty brackets with [tag!="F"].

This is similar to the "near" operator available in some search engines, but it's not identical — while that operator works in both directions (canción near melodía will return both la canción tiene una melodía and la melodía de la canción), the empty brackets wildcard is unidirectional: [lemma="canción"] []{1,4} [lemma="melodía"] will only match la canción tiene una melodía bonita.

 

Querying multiple keys within a single token or "slot"

Multiple keys can be queried on a single token or "slot". This allows you to fine-tune your searches, and is especially useful for eliminating false positives and other irrelevant results. We already saw an example of this in the search operators section with [lemma="ir" & !word="fue|fuimos"], which returns all forms of the verb ir except fue and fuimos. Multiple-key queries can, of course, include any of the keys in the corpus. For example, we can find all verbs in the -ra variant of the past subjunctive with [pos="V.SI.+" & word=".+ra"] (the . character class and the + quantifier are explained in the section on regular expressions).

 

Regular expressions

Regular expressions are search terms that use a combination of normal and special characters to find a certain pattern of text. They're extremely powerful, but rather confusing at first. It's well worth putting in the time to learn the basics, though.

CQP syntax mode uses the PCRE (Perl Compatible Regular Expressions) standard with one main difference: the string start (^) and string end ($) anchors are automatically (and invisibly) inserted at the beginning and end of each query element, respectively. Thus, word=".+iendo" is actually word="^.+iendo$". A PCRE cheatsheet is available here.

 

Regular expression character classes

In addition to using ordinary characters (e.g. á, b, k, ñ, o, t, ü, z) to search for words or parts of words, you can use the following character classes, in combination with the quantifiers detailed below, to search for flexible and complex patterns.

CLASS MEANING EXAMPLE MATCHES
cde Ordinary characters. They're treated as a word or word fragment. amiga amiga
. Any character amig. amiga, amigb, amigc, etc.
[cde] Any character in the set in brackets (c, d or e here) amig[ao] amiga, amigo
[^cde] Any character not in the set in brackets (a, b, f, g, etc. here) ta[^aeiou]a taba, taca, tada, tafa, etc.
[c-e] Any character in the range in brackets (c, d, e here) [k-n]ama kama, lama, mama, nama, etc.
(c|de|fgh) Any character or group of characters in parentheses (c, de, fgh here) amig(a|o|ue) amiga, amigo, amigue

Note that all of these expressions go inside a query statement such as [word="amig[ao]"].

In addition to one-off use and use in combination with a quantifier, the . character class is particularly useful when working with the pos key. You can replace all the slots in a given POS tag that are not relevant to your search with it. So, for example, [pos="V...3.."] will find all types of verbs (main, auxiliary, semiauxialiary), in all tenses, moods and numbers, that are conjugated in third person.

The [^ ]character class can also be extremely useful in POS tags and elsewhere. In order to find all present indicative non-main verbs except 3rd-person ones, you would use this expression: [pos="V[^M]IP[^3].."].

Regular expression character classes can be used alone, with ordinary characters, or with additional character classes. They represent a single character or group of characters when they don't have a quantifier, so [word="ca[st]a"] matches casa and cata, but not casta. To match all three words, you would use [word="ca[st]{1,2}a"] (the braces quantifier is explained below). Note that this would also match the hypothetical cassa, catsa y catta, too.

 

Regular expression quantifiers

Quantifiers allow you to specify how many times the character, character class or group (in parentheses) that is immediately to the left of a quantifier may appear.

QUANTIFIER MEANING EXAMPLE MATCHES
? 0 or 1 occurrences of the item to the left. caros? caro, caros
* 0 or more occurrences of the item to the left. (re)*caro caro, recaro, rerecaro, etc.
+ 1 or more occurrences of the item to the left. ca+ro caro, caaro, caaaro, etc.
{n} Exactly n occurrences of the item to the left. (re){2}caro rerecaro
{n,m} Between n and m occurrences of the item to the left. (re){2,4}caro rerecaro, rererecaro , rerererecaro

 

Reserved characters

The following characters have special meanings inside search expressions.

. ? * + | ( ) [ ] { } ^ $

If you want to search for them you must escape them by adding a preceding backslash (\). So, for example,[word=" \?"] will match a single question mark, while [word="\."] matches a single period. Unless you're searching for punctuation for some reason, you probably won't have to worry about these characters.

 

Special operators

A handful of special operators that function above the token or "slot" level are available.

OPERATOR MEANING EXAMPLE MATCHES
within s Matches must occur within a sentence (utterance). [word="dijo"%c] [] [tag="P"] [tag="V"] within s dijo que me llamó
Doesn't match (// = utterance boundary):
dijo . // Me llamó

<s_utterance="NUMBER"> [] expand to s_utterance

 Display utterance number NUMBER. <s_utterance = "12887"> [] expand to s_utterance All the contents of utterance number 12887.
<s_utterance="NUMBER"> []* </s_utterance> Display utterance number NUMBER. <s_utterance="12887"> []* </s_utterance> All the contents of utterance number 12887. This alternative is longer, slower and may choke on very long utterances.

Troubleshooting

In my experience, at least, the most common source of errors with CQP syntax is using it when the Simple Query mode is selected. This is very easy to do as this mode is the default. And it's hard to recognize because it produces a gargantuan error message that may make inexperienced users think they broke the server.

Not using brackets, or using one too many or one to few of them also causes a catastrophic-looking error message. Just go back and fix your brackets. Note that you can omit everything but the query value in quotation marks (e.g. "perro" or "perro" "vago") and things will work. In this case, the default key is used (word).

A third common source of errors is misplacing operators with regard to quotation marks. A query such as [word="perro"|"gato"] seems to be a perfectly reasonable way to find either of these words in a given slot, but it will fail. The vertical bar |(meaning "or") and all values must be in a single set of quotation marks, like this: [word="perro|gato"].
